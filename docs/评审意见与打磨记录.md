# 五视角自检清单与整改记录（v3.1）

> **说明：** 本文是开发方按五类关注视角做的**自检清单**，不是真实专家的评审结论，**不含任何评分**，也不能作为申报材料中的“专家意见”引用。
>
> 之所以去掉评分：自评分是开发方给自己打分，不构成可复核的证据，把它写在交付材料里反而会削弱可信度。清单本身（下表的“主要问题”与“整改措施”两列）是有价值的——每条都对应代码中的具体改动与测试，请按这两列核对。

## 评审视角与维度（每位 100 分）

| 评审视角 | 关注维度（权重） |
|---|---|
| A 课程思政教学名师 | 融入的自然度与专业结合（40）、案例与来源规范（30）、避免口号化（30） |
| B 教学设计与评价专家 | 目标—活动—评价一致性（40）、课时与环节编排（30）、产物结构与可用性（30） |
| C 教育技术与人工智能专家 | 智能体编排与课堂仿真的合理性（40）、材料依据与可追溯（30）、交互与性能（30） |
| D 数据安全与研究伦理专家 | 权限与密钥（30）、个人信息保护（40）、研究数据边界（30） |
| E 高校教学管理与推广专家 | 上手难度与引导（40）、覆盖的教学文件类型（30）、界面与展示效果（30） |

## 第一轮查出的问题

| 视角 | 问题 |
|---|---|
| A | ① 演示骨架里的思政融入点只写“工程责任”之类的词语，系统自己在示范口号化；② 缺少“口号式融入”的自动提示；③ 没有思政元素参考，一线教师不知从何写起 |
| B | ① 教案看不到“每个目标由哪个环节支撑、在哪里被评价”；② 课堂结束后看不出各环节计划用时与实际用时的偏差 |
| C | ① 上传材料后需要在课堂上看到“老师正在讲哪一段”；② 首页人物插画有 CSS 与 SVG 变换冲突，人物会“旋转”，观感差 |
| D | ① 教师可能把含学生信息的名单、成绩表当材料上传；② 材料原文不应进入研究导出 |
| E | ① 首次进入缺少操作说明；② 首页模块占位过大、图片未显示；③ 顶栏在手机上折行；④ 没有“一键示例”，教师很难快速看到效果 |

## 针对意见的打磨（均已实现并验证）

| 意见 | 打磨措施 | 验证 |
|---|---|---|
| A① | 演示骨架的思政融入点改为情境化示例（“在××任务中设置决策情境：当进度、成本与××冲突时，要求学生给出依据与取舍理由”），并注明“示例表述，请结合实际修改” | V20、`tests/v31-features.test.js` |
| A② | 新增“口号化”检测：融入点过短或只剩价值词、没有专业情境时给出提示；修正了数字列被误判的问题 | 测试 + 编辑器截图 |
| A③ | 新增思政元素参考库（8 类，含与专业结合的引导问题；只给思考框架，不收录政策原文，避免编造条文） | 新建研讨弹窗 |
| B① | 教案新增“目标—活动—评价一致性”视图（编辑器与 DOCX 导出中都有），未被评价的目标标为“未评价” | 编辑器截图 |
| B② | 课堂反馈新增“环节用时（计划 vs 模拟）”、讲解段落完成度与各环节思政相关发言数；超时/未讲完会自动生成修订建议；课堂提前结束时如实说明“未进行到该环节” | 浏览器检查“课堂反馈含各环节计划与模拟用时” |
| C① | 模拟课堂新增“讲解内容（跟学）”面板，教师当前讲到的段落高亮；另有上课计时、环节刻度与剩余时间，1×—60× 倍速可随时切换 | `tests/v31-features.test.js`（课堂时钟与讲解顺序） |
| C② | 首页改用两张真实照片，动效直接做在照片上（缓慢推近/平移、柔光扫过、调色与暗角），删除卡通插画 | 截图 02、11、12 |
| D① | 上传后自动检测身份证号、手机号、邮箱、学号，在预览、提示词和产物中一律隐去；上传区有明确提醒 | 测试：隐私信息不进入产物 |
| D② | 数据库只保存提取出的文字；研究导出不含材料原文；材料可随时删除，删除有审计记录 | 代码审查 + 测试 |
| E① | 首页、教学研讨、模拟课堂首次进入时显示分步浮动指引，顶栏“? 指引”可随时重看 | 浏览器检查“首次进入首页显示浮动操作指引” |
| E② | 首页卡片缩小并垂直居中，使用真实照片 | 截图 |
| E③ | 手机端顶栏只显示图标，不再折行 | 截图 12、18 |
| E④ | 新建研讨中提供“填入示例课程”一键填充 | 新建研讨弹窗 |

## 第二轮复检：仍存在的问题（如实保留）

| 视角 | 问题 |
|---|---|
| A | 思政高亮是词面匹配，只能提示关注点，不能判断融入质量（界面中已说明） |
| B | 课堂环节用时来自模拟时钟（按字数和动作估算），不是真实课堂计时 |
| C | **真实模型（DeepSeek）尚未用真实 API Key 验收**；预设演示的学生台词句库较小，会有重复 |
| D | 个人信息检测基于规则，可能漏检姓名等信息，仍需教师自觉 |
| E | PDF 与旧版 .doc/.ppt 需要先另存为 DOCX/PPTX；课件暂不能导出 PPTX |

## 后续建议（不影响本轮结论）

1. 在管理员后台配置 DeepSeek 的真实 API Key，先点“连接测试”，再用 25 分钟小预算课堂跑一次，补齐 C 项的真实模型验收。
2. 邀请 2—3 位一线教师按《教师使用指南》实际使用一次，把他们的操作卡点记录进 WORKLOG。
