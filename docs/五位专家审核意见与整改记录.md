# 五位专家视角审核意见与整改记录（v5.1，2026-09-25）

> **说明：** 本文是开发方（Claude）按五类国家级教学质量评估专家的关注点，对平台逐项核查后写出的**模拟审核意见**，不是真实专家的评审结论，不能作为申报材料里的“专家意见”引用。每条意见都对应代码中的具体问题，并在本次修改中给出整改和测试证据；做不到或不该由平台做的事项单独列出。

| 视角 | 关注点 |
|---|---|
| 教学设计专家 | 学情依据、目标可观察可评价、目标—活动—评价一致 |
| 立德树人专家 | 育人目标能否落到学生的真实判断上，而不是停在表态 |
| 课程思政专家 | 融入是否自然、少而精，是否“贴标签” |
| 质量评估专家 | 评价过程能否避免偏差、结果能否检验信度 |
| 系统规范专家 | 版本与数据口径、个人信息保护、导入导出安全、无障碍 |

## 一、教学设计专家

**意见 1：学情分析没有学情依据。**

- 研课场生成的“学情分析”只有“先修：【待教师补充】”。
- 教师在“智能体 → 学生智能体”导入的班级画像只用于演课场，研课场完全不读取。
- 结果是教学设计与真实学情脱节。

**整改：**

- 新建研讨时增加“学情依据（班级画像）”选项。
- 选用画像后，“学情分析”段落写入群体统计：先修水平高/中/低人数、表达活跃度、质疑倾向、兴趣分布、教师记录的常见误解，以及对应的教学应对。
- 真实模型模式下，提示词写入同样的统计，并要求“不得编造其他学情数据”。
- 未选画像时，明确写“尚未导入班级画像”，不编造。
- 代码：`server/agents.js learnerSummary`、`server/runs.js prepareSeminar`、`server/dialogue.js`（learners、courseBrief）、`public/js/seminar.js`。
- 测试：`tests/expert-review.test.js` 第 1 项。

**意见 2：教学目标常写成“了解/理解/掌握……”，无法观察和评价。**

**整改：**

- 结构校验新增“目标可观察性”提示：目标只用内隐动词、没有外显行为时，建议改为“能判断/能计算/能说明理由”等。
- 依据的是布卢姆目标分类修订版的动词。
- 代码：`server/artifacts.js validateBody`。测试：第 2 项。

## 二、立德树人专家

**意见 3：课堂反馈只统计“有没有出现思政词”，分不清口号式表态和说理式价值判断，也看不出学生是否在价值问题上表了态。**

**整改：**

- 课堂反馈增加“价值表达”分类，结果写入反馈摘要和修订建议。
- 说理式：含思政词，并给出依据、后果或取舍理由。其余为口号式。
- 同时统计学生（而非教师）表态的条数。
- 口号式多于说理式，或学生没有表态时，给出修订建议。
- 这是启发式判断，已在界面和文档中注明“需人工复核”。
- 代码：`server/runs.js valueTalk / classroomFeedback`。测试：第 4、5 项。

**意见 4：以学生为对象做研究时，缺少知情同意和退出机制。**

**整改：** 科研数据中心提供被试知情同意状态（待确认/已同意/拒绝/已退出），见第六节。

- 只有“已同意”者进入分析与导出。
- 退出可一键删除其全部作答、转录和编码，并保留退出记录，便于报告被试流程。

## 三、课程思政专家

**意见 5：自检只查“偏少”和“口号化”，查不出“贴标签”。** 具体有三种情况：

1. 几乎每一条都挂思政点（过度嵌入）；
2. 各单元的融入点表述雷同（同质化）；
3. 融入点和所在行的专业内容没有任何交集（脱节）。

**整改：**

- `ideologyCheck` 新增三项结果：
  - `embedding`：不足 / 适度 / 过度；
  - `repeated_rows`：表述雷同的条目数；
  - `detached_rows`：与专业内容脱节的条目。
- 编辑器的“课程思政融入自检”面板逐项显示这三项。
- 测试：第 3 项。

**说明：**

- 本地生成的骨架中，各单元融入点用的是同一个“示例表述”句式，因此会被如实标为“同质化”，提醒教师按单元改写。
- 自检只看表述形式，不评价融入的实际质量。

## 四、质量评估专家

**意见 6：人工评分页会带来评价偏差。** 评分者能看到三类信息：

- 发言者身份；
- 发言是“真实模型”还是“本地生成”；
- 其他评价者的分数。

这会产生期望效应和锚定效应。

**整改：** “人工评分”增加**盲评模式**。

- 隐藏发言者、生成方式、运行时间和他人评分。
- 事件顺序按评价者编码确定性打乱，每位评价者看到的顺序不同，但可复现。

**意见 7：多人评分后无法检验评分者一致性，只有“量规未经效度验证”的文字说明。**

**整改：** 科研数据中心“评分一致性”页签，对每个维度计算：

- 加权 κ（2 人）；
- Krippendorff α（有序）；
- ICC(2,1)。

同时支持导入线下评分表。

- 算法用已发表的例题做核对：Shrout & Fleiss (1979) 的 ICC 例题，κ、α 的手算例。
- 测试：`tests/study.test.js`。

**意见 8：没有量表信度、题目分析工具，也没有被试流程、组别、时间点。**

**整改：** 见第六节：量表 α、测试题目分析、项目数据包。

## 五、系统规范专家

| 意见 | 整改 |
|---|---|
| 9. 版本号仍为 `APP_VERSION 3.0.0`，与实际功能不符 | 改为 5.1.0，schema 5.1；数据字典补充 `events.stage`、智能体训练、班级画像的口径 |
| 10. 研究导出缺少 v5 新增数据：智能体训练、班级画像 | 新增导出类别“智能体训练与班级画像（元数据）”：只导出资料份数、切片数、处理阶段、画像人数与字段，不导出资料正文或逐行画像；共享包中班级名以 CP001… 代替 |
| 11. 个人备份不含新数据表 | 备份加入科研数据中心全部数据表；旧备份没有这些表时照常恢复 |
| 12. 无障碍：`<main aria-live>` 会让读屏软件每次换页朗读整页；没有“跳到主要内容”；提示消息没有 live region | 移除 main 的 aria-live，toast 容器设为 `role=status aria-live=polite`，增加跳转链接，编码按钮加 `aria-pressed` |
| 13. 各处表格导入各自为政：缺少统一的个人信息与注入防护 | 统一的智能导入（下表） |
| 14. 产物库只有平铺列表，最多 300 条，版本线重复显示 | 产物库分组，上限提高到 2000，见第七节 |

统一智能导入的防护措施：

- 姓名、学号、身份证、手机号、邮箱等列自动忽略，预览中也不回显其值。
- 内容中出现的个人信息会给出提示。
- CSV 导出做公式注入防护；XLSX 只写内联字符串，不写公式。
- 单个文件不超过 20MB、20000 行。
- 每次预览和导入都写审计日志。

## 七、产物库分类分组

- 可以按课程、层级、模块、状态或来源分组；默认“课程 → 层级”两级。
- 层级为：专业层 → 课程层 → 课堂层 → 练习与评价 → 反馈与反思 → 知识图谱。
- 每条版本线默认只显示最新版，并标明版本数，可展开历史版本。
- 支持搜索、筛选（模块/层级/状态/来源）和排序；分组偏好记在本机。

## 八、没有整改、需要教师或学校完成的事项

- **效度证据：** 七维量规和“思政融入自检”都没有做效度研究。正式研究需要专家评议、预测试和结构效度分析。平台只提供信度和一致性的计算工具。
- **推断统计：** 组间差异、前后测变化、多层模型等请用 SPSS 或 R 完成。平台导出 SPSS 语法和 R 读取脚本，但本身不计算 p 值，避免在样本、假设未经检查时给出结论。
- **模拟数据的边界：** 智能体生成的对话只能用于研究“平台与模拟过程本身”，不能作为真实学生的学习证据。导出中以 `is_simulated` 标注。
- **全面无障碍审计（WCAG 2.1）、等级保护测评、真实课堂验证**：本次没有做。
