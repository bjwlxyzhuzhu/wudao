## 1 本次开发的结论

直接使用现有仓库的账号、模型调用、资料检索、多角色编排、版本记录和统计导出基础，在独立本地副本中开发舞蹈业务。前端重新设计为 A「舞镜智练」和 B「舞安智护」两个产品入口；新增视频处理、姿态指标、教师动作标准、学生训练与风险管理。MCP 接入暂缓，不影响本地开发。

已有代码是可运行的教研与模拟课堂平台，尚不是舞蹈训练系统。此次改造的关键工作是把“围绕文字产物研讨”转为“围绕视频动作证据协同分析”。仅替换品牌、头像和模型 ID，无法完成这个转变。

首版保留原生 HTML/CSS/JavaScript、Node.js 和 SQLite，避免同时迁移 React、TypeScript、Fastify 和 PostgreSQL。优先完成一段真实练习视频从上传到教师确认、再练对比的闭环。之后是否更换框架，以维护成本和实测性能决定。

### 3.1 原来的多智能体究竟怎样协同

默认角色为教研组长、教学设计教师、专业教师、思政教师、评价专家、证据审查教师、行业导师、青年教师。其完整流程为：任务分配 → 讨论交流 → 写作初稿 → 对抗质询 → 打磨修改 → 整合汇总 → 集体评审 → 形成终稿。

这些角色通过代码生成的步骤计划推进，保存发言、质询、回应和修订关系。现有研讨主要按步骤依次执行，不能把它直接宣传为已实现“多个视觉专家并行分析视频”。新项目可以复用事件记录、预算、模型调用和人工介入，但分析阶段、证据对象与角色输出需要改造。

### 3.2 教师智能体与学生智能体的区别

教师智能体：导入老师拥有使用权的资料，检索相关片段、注入口令与表达习惯，再由模型生成建议。目前不是微调大模型，更不等于训练出了真人教师的数字替身。舞蹈示范视频还要经过阶段标注、关键帧和姿态处理，才能进入新的知识与证据库。

学生学习助手：本项目新增，服务真实学生，读取其获授权的练习历史、已发布反馈和下一轮目标。原仓库的“学生智能体”是在模拟课堂里生成发言的角色，两者应分别存储、分别命名，不能把模拟发言当作训练成效。

### 4.2 A 舞镜智练

1. 动作任务：老师发布本次练习动作、示范与要求。
2. 智练场：学生看示范，录制或上传 5–20 秒的单动作片段，执行姿态与多模态分析；具体时长由动作标准决定。
3. 动作对照：支持原视频、骨架叠加和师生双屏；首版按手动阶段同步，后续加入 DTW。
4. 训练报告：做得好的地方、最多 3 条优先改进、时间点证据、下一轮练习提示和复核状态。
5. 教师复核：在同一页查看视频、指标、角色意见和冲突，确认后发布。
6. 再练与成长：记录 R1、R2、R3；只比较同一动作、可兼容的标准及采集条件。
7. 班级工作台：待复核队列、已完成练习、共性问题、需要老师关注的学生及导出。

### 4.3 B 舞安智护

1. 训练前打卡：疲劳、睡眠、酸痛部位和疼痛自报；仅在健康数据授权下保存。
2. 训练后负荷：时长、RPE、训练类型，计算 sRPE × 分钟并显示记录完整性。
3. 动作风险筛查：复用姿态输出，根据已发布规则判定可观测动作模式。
4. 风险解释：显示绿、黄、红或无法判断，列出具体规则、证据和待复核状态。
5. 预防建议：只引用专业教师批准的练习、剂量和禁忌，不让模型自由生成处方。
6. 风险复核台：按紧急程度排序，支持修订、转介建议、跟进和关闭记录。
7. 班级风险看板：有效打卡、负荷异常、未处理预警和复核情况；教师按职责查看必要信息。

## 5 新的多智能体协同设计

### 5.1 分析链路

采集与授权 → 姿态质量检查 → 指标计算 → 已发布规则匹配 → 一次多模态感知 → 有限并发的角色分析 → 证据仲裁 → 教师复核 → 学生报告 → 下次练习对比。

一次多模态感知由关键帧和文本构成，不要求首版具备完整视频或音频端到端理解。角色分析复用这一次感知的结构化结果，避免每个角色重复上传同一段视频。视觉模型观察不替代关键点测量；测量结果也不能自动等同于专业评价。

### 5.2 A 的角色

| 角色 ID | 名称 | 职责与输出 | 首版 |
| --- | --- | --- | --- |
| a_basic | 基本功教练 | 按教师检查点解释基础姿态、控制与稳定问题 | 启用 |
| a_axis | 形体轴线助手 | 肩胯关系、躯干倾斜及支撑稳定，引用已验证指标 | P1，可先由基本功角色覆盖 |
| a_technique | 动作技术助手 | 路线、动作阶段、幅度与时序，引用真实阶段结果 | P1 |
| a_expression | 舞蹈表现助手 | 延伸、连贯与质感的描述性建议，供教师参考 | P1 |
| a_safety | 训练安全助手 | 解释教师安全规则，指出降低幅度或需要现场查看的情况 | 启用 |
| a_eval | 教学评价助手 | 检查点达成状态、与上次已确认反馈比较 | 启用 |
| a_arbiter | 证据仲裁助手 | 合并、去重、核对证据、记录冲突，输出最多 3 条改进项 | 启用 |

最小分析配置为 1 次视觉感知、3 个专业角色和 1 次仲裁，共最多 5 次正常模型调用，不含受控重试。角色总数与单次实际调用数分别展示；未启用角色不得显示成已分析。

| --- | --- | --- | --- |
| b_screen | 动作模式筛查 | 解释规则命中的膝足对线、骨盆稳定等模式 | 启用 |

B 的紧急提示不等待模型或老师上线。规则已触发时先显示保守提示并通知授权教师；后续专业教师复核形成正式结果。安全提示、风险草稿、正式复核结果应分开标识。

### 5.4 协同必须落到数据结构

每条角色发现至少包含：`finding_id`、`role_id`、`checkpoint_id`、`statement`、`evidence_refs`、`uncertain`、`recommended_action`、`needs_review`。模型自报 confidence 仅是未校准的辅助信号，不能单独用于判断安全。

证据引用只允许指向本任务内、当前用户有权访问的指标、关键帧、规则版本及教师标准。服务端校验引用是否存在，不能只验证 JSON 能否解析。冲突记录包含双方发现 ID、冲突点、处理建议和教师裁决。没有证据、视角错误、关键点不足或引用失效的结论不进入确定性报告。

“最多 3 条”只限制普通训练优先项，不能截掉安全红旗。安全提醒单独显示。教师判定优先于模型建议，确定性安全规则不可被模型静默删除。

## 6 前端页面重做方案

### 6.1 页面替换关系

| 原页面 | A 的新页面 | B 的新页面 | 处理方式 |
| --- | --- | --- | --- |
| 首页教研／课堂双入口 | 今日练习与训练任务 | 今日状态与待处理提醒 | 重写布局及内容 |
| 研课圆桌 | 动作标准与教师分析工作台 | 规则与风险复核工作台 | 复用消息、进度机制，重写业务 |
| 模拟课堂 | 真实学生智练场 | 真实训练筛查 | 视频为主体；模拟学生逻辑不接入 |
| 产物库 | 动作标准、示范、训练报告 | 规则版本、预防练习、风险报告 | 复用版本思想，新建业务对象 |
| 智能体中心 | 舞蹈教师资料与角色设置 | 风险知识与练习资料 | 改造检索维度、来源及审核状态 |

### 6.2 A 学生端

视觉采用深灰或暖黑背景、浅色文字和低饱和强调色；舞者视频与动作证据占主位。手机端底部导航为“练习／记录／我的”，打开默认看到本次任务和继续练习入口。

智练场顺序：选择动作 → 看老师示范 → 拍摄指导 → 上传并分析 → 看结果 → 再练。桌面端视频约占 60% 宽度，反馈约占 40%；手机端上下排列，反馈紧接视频。点击问题卡片跳到相应时间段，避免把角色聊天堆在学生首屏。

结果页固定显示来源、分析状态和教师状态。遇到低置信度，显示“这个角度无法判断，请按提示重拍”，不输出武断分数。复核前可显示采集质量与客观测量；完整教学结论在确认后发布。

### 6.3 A 教师端

动作标准页：示范播放器、阶段时间轴、检查点／口令编辑器。支持给 5–10 秒片段标记动作阶段；AI 只能生成草稿，由老师发布。

复核工作台：左侧视频和指标，中间角色意见与证据，右侧冲突及最终反馈编辑。显示实际任务状态，而不是以动画假装专家分析。圆桌可以作为折叠的角色概览，但视频和待裁决问题优先。

班级页显示待复核、已完成和需要跟进的训练任务。R1／R2 对比页区分“指标变化”“教师判定改善”和“无法比较”，避免将数值增加一律视为进步。

### 6.4 B 学生与教师端

浅色背景、青绿色主色；黄红仅用于风险提示，并同时显示文字与图标。学生首页先打卡，再进入今日建议、筛查及负荷记录。人体部位图用于选择自报不适部位，不表示系统诊断定位。

教师复核页优先展示规则命中、自报、数据缺口和最近训练，而不是一个没有依据的风险总分。待复核红旗置顶；关闭预警需记录专业教师处理意见。另一位教师只读取其教学安排所需的提醒，不默认看到健康自由文本。

### 6.5 共用状态与可用性

- 页面必须覆盖空状态、处理中、部分成功、失败、取消、待复核、已发布和已撤回。
- 手机视频拒绝权限时允许选择本地视频；采集说明提示系统浏览器与支持的格式。
- 进度以实际阶段完成情况表示，耗时未知时不显示虚假的固定百分比。
- 关闭页面后可从记录页恢复查看；重复点击分析只得到同一有效任务。
- 键盘可操作主要按钮；视频控件与颜色标签有文本说明；移动端无横向溢出。

### 7.3 数据设计

首版单实例使用独立 SQLite 库，视频与关键点序列存于应用管理的文件存储，数据库只存元数据与引用。所有新增领域表通过迁移版本升级；不将视频 base64 长期塞进原 JSON 导入接口，也不将健康数据混入模拟课堂研究表。

核心新增对象：`cohorts`、`cohort_members`、`consents`、`media_assets`、`dance_actions`、`action_standards`、`training_sessions`、`pose_results`、`metric_results`、`analysis_runs`、`agent_findings`、`review_decisions`、`feedback_versions`。B 再新增 `health_checkins`、`load_logs`、`risk_rule_versions`、`approved_exercises`、`risk_assessments`、`risk_alerts`。

命名注意：原数据库 `sessions` 是登录会话，舞蹈练习必须叫 `training_sessions`；原 `runs` 是教研／课堂运行，避免在没有迁移的情况下直接复用其业务语义。

每次分析固定保存产品、动作标准版本、模型配置／模型 ID、提示版本、姿态版本、指标版本、规则版本、授权状态和输入摘要哈希。当前学生看板以发布版本为准；后续重新分析生成新版本，不覆盖老师已发布反馈。

产品字段不代替权限判断。学生查询必须限定本人，教师查询必须限定班级及职责；媒体下载、缓存结果、导出和后台任务读取采用同一权限规则。授权撤回需停止后续分析，撤销访问，并按策略清理原片、关键帧及派生数据。

### 7.5 后台任务与重试

正常链路：CREATED → POSE_PENDING → POSE_READY → METRICS_READY → AI_PROCESSING → WAITING_REVIEW → PUBLISHED。质量失败进入 NEEDS_RECAPTURE，数据不足进入 INSUFFICIENT_DATA；另有 FAILED、CANCELLED、WITHDRAWN。失败时保留最后成功阶段与错误码。

同一输入、标准和规则版本使用幂等键。重新提交不能重复扣减预算、发布或提醒；任务加锁、租约过期可恢复。每次模型尝试记录状态与耗时；前端刷新不会重启整个分析。原 `jobs.js` 的重启暂停方式可先复用，再补充训练阶段恢复。

模型并发通过队列限流，与原 `models.js` 并发配置一致。不能直接对所有角色无上限 `Promise.all`，否则现有适配器会报并发上限错误。

## 8 多模态模型接入要求

模型分为视觉感知和文本推理两个配置项。V2.0 所列 `qwen3.8-omni-flash` 仅作为待核实候选，本版不把其名称、上线时间或可用性当作既成事实。首版目标能力是多图片与文字输入、文本输出；音频分析后置。

接入时验证：账号地域、准确模型 ID、图片数量和大小限制、流式要求、内容块格式、结构化输出支持、token 统计及费用。模型列表只能证明某个 ID 可见，不能证明它具备所需视觉能力，必须提交获授权样例验证。

适配层提供 `analyzeFrames`、`analyzeRole`、`arbitrate`、`getCapabilities` 和 `healthCheck`。保留现有服务端密钥管理；云端只发送经授权的最小关键帧、指标摘要和必要教学文本。关键帧即使处理了脸部仍可能识别个人，不等于可以免除授权。

结构输出先解析，再做字段类型、枚举、数值范围、证据引用与教师库引用校验。失败最多进行一次结构修复；网络重试与结构修复共享任务预算上限，避免乘法式重试。视觉失败则基于有效指标和规则继续；文本也失败则仅显示指标与规则，等待老师，不生成假的 AI 意见。

成本和性能按实际调用记录：首版 A 正常链最多 5 次调用；设并发、每日预算和任务总超时。测试报告分别记平均、P50、P95、失败率和降级次数，不以某一次演示的速度承诺全部学生体验。

## 9 姿态指标与风险规则边界

首批动作由侯敏老师选择，建议从可稳定拍摄的慢速蹲类、控腿或单腿支撑类动作中选 3 个，先用真实教室视频验证。首版优先计算膝角、躯干倾斜、肩线、骨盆侧倾代理和保持阶段稳定性，不默认支持极限幅度或快速跳跃分析。

每个指标明确坐标系、是否使用 world landmarks、左右命名、镜像处理、视角、单位、滤波、最低有效帧数量、归一化分母和适用阶段。2D 投影与模型估计的 3D 坐标分开标识，不能称为经过标定的医学测量。

FPPA 必须区分“直线为 180° 的几何夹角”和“中立为 0° 的有符号偏离量”；左右腿符号统一后才可配置阈值。关键点可靠性、视角和可见度不满足条件时返回 null 与原因，不能用 0 表示缺失。躯干长度或小腿长度接近 0 时拒绝除法。

风险规则包含版本、适用动作、指标、比较符、阈值、单位、质量门槛、理由、练习引用、确认人及生效时间。未确认规则停用。缺记录、某项无效或规则覆盖不足时显示无法判断。周负荷分母为零、日志天数不足时不计算增长率；历史不足时先展示已记录值，不推测常态。

风险报告只表示观测到的模式与自报状态，不输出疾病诊断。所有阈值、红旗规则和预防剂量由专业教师提供与复核。
