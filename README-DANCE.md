## 1. 启动

需要 Node.js ≥22.13、npm、系统 tar，以及首次下载姿态资源时可访问官方 npm 与 Google 存储。无新增 npm 运行时依赖。

在 `dance-agents` 目录运行：

```powershell
npm run setup:pose
npm run init:dance
npm run start:dance
```

- A：[舞镜智练](http://127.0.0.1:8790/wujing)
- B：[舞安智护](http://127.0.0.1:8790/wuan)
- 模型管理：[管理员登录](http://127.0.0.1:8790/admin/login)
- 账号：`.local/dance-data/local-access.json`，随机密码，仅本机保存，已忽略提交。
- 数据：`.local/dance-data/`，包括数据库、加密主密钥、已授权媒体。不要上传 GitHub 或公开共享。
- 退出服务：终端 `Ctrl+C`。再次初始化不会覆盖现有账号密码。

### 容器／GitHub 镜像直接体验

运行 `docker compose up --build -d` 会开启部署演示模式，并在首次启动的数据卷中自动创建以下账号。密码只以哈希形式进入运行时数据库，不会打包进镜像数据库；这些公开密码只适合验收演示，不能直接用于公网生产环境。

| 身份 | 账号 | 密码 | 入口 |
| --- | --- | --- | --- |
| 管理员 | `admin01`、`admin02` | `Admin123` | `/admin/login` |
| 舞蹈教师 | `teacher01`、`teacher02`、`teacher03` | `Teach123` | `/wujing` |
| 学生 | `student01`—`student06` | `Student123` | `/wujing` 或 `/wuan` |
| 风险复核教师 | `medic01` | `Medic123` | `/wuan` |

`teacher01`、`teacher02` 和 `student01`—`student03` 属于 `dance-a` 班；`teacher03` 和 `student04`—`student06` 属于 `dance-b` 班，数据按班级隔离。已有账号不会因容器重启被覆盖或重置。正式部署方法见 [GitHub 与千问部署说明](DEPLOY-GITHUB.md)。

完整演示步骤见 [账号密码与操作手册](docs/账号密码与操作手册.md)，登录、Cookie、会话令牌和模型密钥的处理方式见 [认证与凭证处理说明](docs/认证与凭证处理说明.md)。

默认只监听 `127.0.0.1`，手机不能通过电脑 IP 直接访问。本轮不部署公网，不改变防火墙。

`DANCE_DATA_DIR` 可指定独立数据目录，`PORT` 可指定端口。可写入被忽略的 `.env`，启动和账号初始化均会读取。保留上游系统时，`npm start` 仍使用原启动方式及数据目录。

## 2. 已实现功能

| 模块 | 当前能力 |
| --- | --- |
| 双项目界面 | A 深色训练工作台、B 浅色健康工作台；侧栏导航和移动端样式 |
| 账号权限 | 学生、舞蹈教师、风险复核教师；本人与班级隔离；管理员配置模型 |
| 动作标准 | 一位站姿、二位站姿、二位 plié 蹲、Tendu、Passé、Dégagé 六个动作入口；教师填写视角、要求、检查点并发布版本 |
| 练习采集 | 选择本地 3–30 秒、≤20MB 的单人视频；优先 H.264 MP4，也支持浏览器可解码的 WebM/MOV |
| 姿态引擎 | 本机 MediaPipe，约 10fps，33 点骨架；低置信度、多人及短片段质量检查 |
| 几何指标 | 膝角、躯干倾斜、肩线倾斜、骨盆侧倾代理、髋中点摆动；侧面不输出正面专属指标 |
| 教学闭环 | 练习 → 指标 → AI 草稿或明确降级 → 教师复核 → 反馈版本 → 再练与最近两轮同标准比较 |
| 多角色分析 | 视觉观察后依次调用基本功、训练安全、教学评价、证据仲裁；最多五次模型调用 |
| 教师反馈 | 优点、最多三项改进、下一轮提示；采纳／修改／否决记录；并发版本冲突校验 |
| 健康与负荷 | 疲劳、睡眠、疼痛和部位自报；训练分钟 × RPE；风险教师查看本班记录 |
| 隐私控制 | 教学、云端关键帧、原视频分项授权；健康独立授权；撤回删除；原视频 30 天到期清理 |

界面示意舞者不是分析结果。无模型时不生成伪 AI 结论；无专业风险规则时始终显示“未评估”，不显示绿色安全结论。

## 3. 第一次体验

1. 使用 `teacher01` 登录 A，在“动作标准”填写并发布真实教学要求。系统不会预置冒充专业审核的标准。
2. 退出，用 `student01` 登录。选择动作和视频，勾选教学用途。云端分析、服务器保存原片均为独立可选项。
3. 提取完成后查看指标。质量不足会要求重拍；未配置模型仍可进入教师复核。
4. 切换教师，在“训练复核”查看本班记录。原片只有学生单独同意保存时才能查看。
5. 教师填写并发布反馈。学生在“成长记录”查看，按同一标准再次练习后可对比测量变化。
6. 在 B 填写健康状态与负荷。使用 `medic01` 查看本班健康记录；舞蹈教师账号不能查看健康明细。

本地骨架叠加保留在当前练习页面的内存中；重新打开历史报告目前只提供指标和已授权原片，不恢复逐帧骨架。数值变化不自动等于改善。

## 4. 多模态模型配置

当前已实现 OpenAI 兼容视觉适配和 mock 契约测试。部署时设置 `DASHSCOPE_API_KEY` 后，会在首次启动时自动创建千问视觉配置并供舞蹈智能体使用；密钥不会进入前端、Git 仓库或镜像层。

1. 用 `dance_admin` 在管理员后台“模型与 API Key”中创建配置。
2. 选用支持图片输入及流式 `/chat/completions` 的 OpenAI 兼容供应商。填写已核实的 base URL、模型 ID 和密钥；不要沿用上游默认的纯文本模型预填值。普通“连接测试”成功不等于图像输入成功。
3. 运行 `npm run models:dance` 查看配置的 `provider_id`。此命令不输出密钥。
4. 在 `.env` 中设置如下配置并重启服务；这里填配置 ID，不是供应商的模型名称：

```dotenv
DANCE_VISION_PROVIDER_ID=填写已有视觉配置的provider_id
DANCE_TEXT_PROVIDER_ID=填写已有文本配置的provider_id
```

`DANCE_TEXT_PROVIDER_ID` 可省略，默认复用视觉配置。不要把真实密钥写入前端或提交 Git。

自动配置默认使用 `qwen3-vl-plus` 和 `https://dashscope.aliyuncs.com/compatible-mode/v1`。阿里云建议把 `QWEN_BASE_URL` 改为控制台显示的业务空间专属 API Host；API Key 与服务地域必须一致。环境变量方式详见 [GitHub 与千问部署说明](DEPLOY-GITHUB.md)。

实际链路：本机 MediaPipe 提取 33 点骨架与角度 → 最多 6 张遮挡面部并叠加骨架线的关键帧 + 教师标准与指标 → 千问视觉观察 → 三个教学角色 → 仲裁从已有发现中选最多三项并给出保守合规预判 → 教师复核。面部关键点不可靠时跳过对应关键帧；遮挡不等于完全匿名。

角色依次执行以遵守原适配层并发限制，不是四个模型的并行投票。证据 ID 有白名单校验，但还不能证明模型语义完全正确。学生接口不返回未经确认的 AI 草稿。

无授权、无关键帧或无模型时降级为指标模式；超时、格式错误保留有效结果交给教师。供应商调用可能收费：首版限制同时分析两轮、单轮最多五次调用，尚未接入上游积分结算和按用户费用预算，不能直接开放公网。

## 5. 技术落点

| 路径 | 职责 |
| --- | --- |
| `public/dance/` | 双项目页面、样式、视频解码、MediaPipe 与纯几何指标 |
| `server/dance/service.js` | 权限、标准、训练、复核、授权媒体、健康记录 |
| `server/dance/analysis.js` | 多模态观察、角色分析、证据校验和降级 |
| `server/dance/migrations/001.sql` | 舞蹈领域表与索引 |
| `server/server.js` | `/api/dance` 路由、鉴权视频 Range、页面和 WASM CSP |
| `scripts/` | 资源安装、开发账号初始化和模型配置 ID 查询 |
| `tests/dance.test.js` | 新领域接口、权限、指标和多模态 mock 回归 |

核心状态：`POSE_PENDING → METRICS_READY → AI_PROCESSING → WAITING_REVIEW → PUBLISHED`；低质量进入 `NEEDS_RECAPTURE`，撤回进入 `WITHDRAWN`。浏览器提取在创建服务端记录前执行，避免本机取消产生空记录。后台分析不依赖页面存活；服务重启会中断在途模型调用并保留指标交给教师，不自动续跑云端调用。

## 6. 当前验证结果

- 舞蹈与部署专项测试：12/12 通过（动作闭环 9 项、账号与千问启动 3 项）。
- 完整回归 93 项：93 通过、0 失败。原交付验证记录见 [VERIFICATION.md](VERIFICATION.md)。
- 浏览器使用独立 `.local/qa-data` 验证：教师发布测试标准 → 学生选择测试视频 → 真正运行 MediaPipe → 指标 → 教师复核发布 → 学生查看反馈；授权原片能够解码播放。
- 测试视频来自 Google 官方公开测试图片生成的约 3.7 秒静态片段；检测 37 帧，覆盖率 100%，无云端调用。只证明工程链路可运行，不证明舞蹈动作识别或医学筛查准确率。
- 浏览器验证 B 的状态保存、20 分钟 × RPE 4 = 80 的负荷计算。测试数据与正式本地开发目录分开。
- 检查 1280px 桌面和 390px 手机视口，A/B 无页面横向溢出；手机账号退出入口可用。
- 真正学生的动态视频、遮挡、镜面、侧身、手机性能，以及真实视觉供应商仍待实测。
